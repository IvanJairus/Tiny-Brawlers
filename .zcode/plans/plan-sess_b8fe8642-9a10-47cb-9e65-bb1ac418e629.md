# Rencana: Membuat Tiny Brawlers Nyaman Dimainkan (Game Feel First)

## Diagnosis singkat (hasil eksplorasi)

Akar masalah "tidak nyaman" bukan satu bug, melainkan kombinasi:

1. **Arah tembak selalu = arah gerak** — `boot.ts:287-288` (`aimX: moveX`) dan `keyboard.ts:91-92`. Tidak bisa mundur/menyamping sambil menembak. Ini masalah kenyamanan terbesar di desktop.
2. **Gerakan tanpa inersia** — `buddy.ts:95-100` set velocity langsung (start/stop instan, terasa kaku).
3. **Tidak ada tabrakan antar entitas** — buddy menembus buddy dan tank; hanya obstacle statis yang di-resolve (`obstacles.ts:92-131`).
4. **Knockback = teleport posisi** (`step.ts:475-476`), ledakan tidak memberi knockback sama sekali, dan granat (320 dmg, falloff min 40% = 128 di tepi radius) one-shot hampir semua kelas.
5. **Tap keyboard sub-tick hilang** — hanya tombol touch yang di-latch; ketukan pendek antara tick tidak terbaca.
6. **Spawn peluru melompati 0.64 unit pertama** (`step.ts:528`) — nembak tembus tembak/musuh jarak nol.
7. **Tank rusak**: driver double-fire (shell + senjata pribadi, `step.ts:51` vs `674-681`), driver tetap "jalan" sendiri (drift), tidak ada tombol turun.
8. **Hitstop dimatikan oleh bug kondisi terbalik** — `bridge.ts:118-123` selalu `false` di browser, jadi dampak pukulan terasa flat.
9. **Bot tanpa pathfinding & tembak tanpa cek LOS**, resep yang ditumpuk manusia bisa "dicuri" bot (`step.ts:295`), peluru nyasar dekat pad memicu build otomatis.
10. Map: layout obstacle hardcoded tunggal (`obstacles.ts:41-74`), arena 64×64 terasa kosong dengan 8 buddy, arena clamp ±31 membuat "void" di jarak 46 mustahil tercapai (fitur mati).

Struktur arsitektur sehat (sim deterministik 30 Hz murni + render Three.js + HUD DOM), jadi semua perbaikan dilakukan **di dalam kontrak yang ada**: fisika di `src/sim/domain/`, tanpa `Math.random`/DOM di sim, InputCmd 8-bit tetap jadi batas input netplay. Setiap milestone ditutup dengan `vitest` + e2e terkait + cek manual `npm run dev`.

## Milestone 1 — Mouse aim + input buffering (fondasi kenyamanan)

**Skema twin-stick desktop: WASD gerak bebas, karakter menembak/pukul ke arah kursor.**

- `src/platform/input/keyboard.ts`: tambah pelacakan posisi kursor (mousemove pada canvas).
- `src/boot.ts` `mergeAxes()` (`:279-294`): jika pointer aktif (desktop, kanvas hover), hitung titik dunia di ground plane y=0 via raycast kamera (kamera & world sudah ada di boot), aim = normalisasi `(worldPoint - posisiPlayer)`, kuantisasi lewat `encodeInput` yang sudah ada. Touch tetap aim=stick; fallback aim=move jika kursor tak pernah bergerak.
- `src/sim/domain/buddy.ts` `stepBuddy()` + `src/sim/core/step.ts:47`: konsolidasikan heading — heading mengikuti **aim** saat aim aktif (hypot > 0.2), jika tidak mengikuti velocity; hapos flip-flop antara dua sumber. Sim sudah punya sumbu aim di InputCmd, jadi tidak ada perubahan protokol netplay.
- Reticle: sembunyikan kursor sistem saat playing (`cursor:none`), gambar crosshair di `src/render/spriteStage.ts` + indikator arah singkat di kaki karakter.
- **Input buffering**: latch edge untuk tap keyboard/mouse (attack/grab/build) — pindahkan pembersihan `touchLatched` dari dalam callback per-tick (`boot.ts:272-274`) ke setelah `stepper.push()` selesai, agar semua step dalam satu frame melihat latch dan tap <33ms tidak hilang (aman: grab/build edge-triggered di sim via `prev`).
- Tes: unit test determinism tetap lolos (aim dari InputCmd), e2e layout tetap lolos, tambah e2e kecil "klik kanan-atas → peluru ke arah itu".

## Milestone 2 — Fisika: inersia, tabrakan antar entitas, knockback impuls

- **Akselerasi/decelerasi** di `stepBuddy()` (`buddy.ts`): velocity mendekati target secara linear per tick (capai ~90% speed dalam ~0.15 s, berhenti dalam ~0.1 s) — deterministik karena dt tetap `TICK_S`.
- **Buddy-vs-buddy & tank-vs-buddy**: circle-circle pushout simetris (radius buddy 0.48, tank 1.15) setelah gerakan di `step.ts`; buddy KO di-skip. Squeezed-between-boxes: tambahkan 2 iterasi resolve + cap per tick agar tidak jitter.
- **Knockback jadi impuls**: melee (`step.ts:475`) menambah velocity, bukan teleport; ledakan memberi impuls radial skala falloff dengan `knockTimer` singkat (~0.25 s) saat input gerak dikurangi — terasa "kena hentakan" tapi tetap bisa dikontrol.
- **Fix spawn peluru** (`step.ts:528`): sweep dimulai dari pusat owner (muzzle offset visual saja) — nembak jarak nol tidak menembus.
- Tes: unit test baru (dorong dua buddy bertumpuk → terpisah; knockback meluruh; peluru jarak nol kena target).

## Milestone 3 — Combat feel & balancing (angka boleh diubah)

- **Ledakan**: falloff tepi 40% → ~15–20% sehingga granat tidak one-shot di rim (center tetap mematikan); plus knockback dari M2.
- **Range senjata dipatok**: life peluru = `range/speed` (shotgun 11 u, pistol sesuai def) — `weapon.ts` vs `step.ts:28-31`.
- **Melee**: maksimum 2 target terdekat per pukulan (bukan semua musuh dalam cone).
- **Pistol**: damage 30→22, cooldown 0.33→0.4 s — tetap infinite ammo tapi tidak mengungguli senjata racikan.
- **Aktifkan hitstop**: balik kondisi `frozen()` (`bridge.ts:118-123`) agar berjalan di browser + flash putih singkat pada target kena pukulan (warna instance di `chibi.ts`).
- Tes: update angka di unit test yang ada; e2e visual snapshot di-refresh.

## Milestone 4 — Mekanik: tank & pad

- **Tank**: E untuk naik **dan turun**; saat mengemudi driver buddy dikunci ke posisi tank (tidak menjalankan `stepBuddy`/fire pribadi) — hapus double-fire & drift (`step.ts:51`, `653-681`).
- **Pad**: hadiah build diberikan ke pemilik input build / manusia terdekat, bukan bot acak (`step.ts:295`); hapus auto-build oleh peluru nyasar (`step.ts:554-559`) — build hanya via tombol R/Q atau pukul pad.
- **HUD pad card**: tim mengikuti pemain lokal (`view.ts:59` hardcoded `'red'` → tim pemain).
- **Determinism hash**: masukkan HP obstacle & powerups ke `hashWorld()` (`world.ts:153-171`) agar divergensi brick-damage netplay terdeteksi.
- Cleanup kecil: hapus type-cast `(b as {prevX?...})` di `bridge.ts` (field sudah ada di record), satukan `respawnDelayFor` dengan angka 5 hardcode di `fell()`.

## Milestone 5 — Arena & map

- **Layout obstacle per biome**: 3 set layout simetris (point-symmetric, fair untuk 4 base) dipilih deterministik dari biome/seed di `obstacles.ts` — sim tetap deterministik.
- **Pacing arena**: kecilkan `ARENA_HALF` 32→26 (base ±21.2→±17.5, ring crate awal menyusut) + kecilkan void mati (`VOID_DISTANCE` 46 → di dalam clamp, atau hapus fitur teleport-KO yang mustahil tercapai).
- Tes: determinism gate 3× run, test fairness simetris (mirror layout identik), e2e visual.

## Milestone 6 — GUI/UX polish

- Volume slider master/musik/SFX di pause settings (`storage.ts` + `audio/graph.ts` gain; sekarang fixed 0.7).
- Buku resep dibangun dari `recipes.ts` (satu sumber kebenaran) — hapus duplikasi hardcoded di `screens.ts:158-255`.
- Satukan angka sihir: `BUNKER_MAX_HP` di `bind.ts:215`, ukuran ring touch 118px/-59px CSS↔JS (`touch.ts:47-49` vs `screens.css`).
- Perbaiki toggle quality runtime yang no-op (terapkan pixel-ratio langsung, atau hapus toggle).
- Semua teks & label tetap bahasa Indonesia.

## Milestone 7 — Bot yang tidak mengganggu

- Disiplin LOS: jangan menembak jika `hitObstacleAlongSegment` menghalangi (fungsi sudah ada).
- Steering: stuck-detection (perpindahan < ambang selama 1 s → detour tegak lurus) sebagai pengganti A* penuh — murah dan deterministik.
- 3 tingkat kesulitan (mudah/normal/sulit): reaksi, error aim, agresi — pakai `rngAi` yang sudah dialokasikan tapi tak terpakai.
- Bot tidak mencuri crate yang lebih dekat ke manusia (penalti ally-closer sudah ada, perketat untuk pemain).

## Urutan eksekusi & definisi selesai

M1 → M2 → M3 adalah inti "game feel" (pilihan Anda). M4–M7 menyusul, masing-masing independen dan bisa dihentikan di antara milestone.

Setiap milestone ditutup dengan:
1. `npx vitest run` hijau (termasuk gate determinisme & layer-purity).
2. Playwright e2e terkait hijau (`npx playwright test`).
3. Cek manual di `npm run dev`: main 1 round vs bot, rasakan kontrol.
4. Commit per milestone dengan pesan konvensional.
